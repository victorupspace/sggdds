# Design Tokens

Os tokens do SGGD são importados das collections de variáveis do Figma e
publicados no pacote `@government/tokens`. O inventário visual dos tokens
primitivos está disponível em `Foundations`.

## Estratégia em quatro camadas

Cada collection do Figma vira um tier, com prefixo próprio nas variáveis CSS:

| Tier        | Collection no Figma     | Prefixo CSS        | Conteúdo                                   |
| ----------- | ----------------------- | ------------------ | ------------------------------------------ |
| `primitive` | Global: Core            | `--ds-primitive-*` | Escalas brutas: cor, spacing, tipografia…  |
| `brand`     | T1: Sampa Design System | `--ds-brand-*`     | Paletas de marca, identidade e utilitárias |
| `semantic`  | T2: Semantics           | `--ds-semantic-*`  | Papéis de cor e estilos de texto           |
| `component` | T3: Components          | `--ds-component-*` | Decisões por componente (button, input, …) |

Os aliases criados no Figma são preservados como referências no CSS gerado —
por exemplo, `--ds-component-button-color-background-primary-default` resolve
para `var(--ds-semantic-color-background-brand-primary-default)`, que por sua
vez resolve para `var(--ds-brand-color-brand-red-primary)`. Isso mantém a
cadeia de decisão do Figma inspecionável em runtime e prepara o terreno para
theming sem tocar nos componentes.

Os componentes React consomem o tier `component` sempre que a decisão
equivalente existe na collection T3 com o mesmo valor; papéis ainda sem token
de componente (ou com valor divergente aguardando alinhamento com o design)
permanecem nos tiers `semantic`/`primitive`.

## Pipeline

1. Coloque os exports brutos do Figma em `packages/tokens/src/raw`
   (ver o README daquele diretório para o mapeamento arquivo → collection).
2. Execute `pnpm tokens:validate`.
3. Execute `pnpm tokens:build`.
4. Consuma as variáveis CSS geradas em `packages/tokens/dist/css/tokens.css`
   (ou via `@government/design-system/tokens.css`).
5. Use `packages/tokens/dist/json/tokens.json` para consumo programático.

O Style Dictionary também gera saídas nativas a cada build: Swift em
`platforms/ios` e XML de resources em `platforms/android`.

## Decisões de normalização

- Chaves são normalizadas para kebab-case, espelhando os nomes de variáveis
  CSS (`SemiBold` → `semi-bold`, `Component sizing` → `component-sizing`).
- O valor base de grupos com estados (`$root` no export do Figma) vira o token
  `default` do grupo.
- O grupo `sucess` (grafia do Figma) é normalizado para `success`; o caminho
  original é preservado em `sggd.figmaPath`.
- Números com escopo de layout (`WIDTH_HEIGHT`, `GAP`, `FONT_SIZE`, …) viram
  dimensões em `px`; durações de motion e opacidades permanecem numéricas.
- Pesos de fonte nomeados (`SemiBold`) viram valores numéricos (`600`), com o
  nome original em `sggd.figmaFontStyle`.
- `aliasData` do Figma vira referência DTCG entre tiers; o valor resolvido do
  export fica registrado em `sggd.figmaResolvedValue`.
- As sombras `--ds-semantic-shadow-*` ainda não existem nas collections do
  Figma e são mantidas em `src/raw/web-extras.tokens.json` até serem
  incorporadas lá.
