# Figma Integration

O Design System visual vive no Figma. Este repositório recebe exports de
tokens e especificações de componentes como insumo técnico versionado.

## Collections e tiers

As variáveis do Figma estão organizadas em quatro collections, e cada uma
corresponde a um arquivo em `packages/tokens/src/raw` e a um tier no código:

| Collection no Figma     | Arquivo                     | Tier        |
| ----------------------- | --------------------------- | ----------- |
| Global: Core            | `global-core.tokens.json`   | `primitive` |
| T1: Sampa Design System | `t1-sampa.tokens.json`      | `brand`     |
| T2: Semantics           | `t2-semantics.tokens.json`  | `semantic`  |
| T3: Components          | `t3-components.tokens.json` | `component` |

## Como importar tokens

1. Exporte as Figma Variables em JSON (uma collection por arquivo).
2. Salve por cima do arquivo correspondente em `packages/tokens/src/raw`.
3. Execute `pnpm tokens:validate`.
4. Execute `pnpm tokens:build`.
5. Revise o diff de `packages/tokens/src/normalized` e dos artefatos gerados
   antes de abrir o pull request — o build reporta aliases que não resolvem
   entre as collections.

Os aliases entre collections (`aliasData` no export) são convertidos em
referências e preservados no CSS final; renomear ou remover uma variável no
Figma aparece no build como referência não resolvida, nunca como quebra
silenciosa.

Quando um nome vindo do Figma precisar de correção técnica segura (ex.:
`sucess` → `success`), o caminho original é preservado em `sggd.figmaPath`
automaticamente pelo pipeline.

Não inclua segredos, dados sensíveis, nomes de usuários ou artefatos privados
desnecessários no JSON exportado.
